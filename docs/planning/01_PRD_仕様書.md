# こんだて日和 — 製品要求仕様書（PRD） v1.0

- 作成日: 2026-11-17
- ステータス: 企画案 / 未実装
- 対象: 日本国内の2〜5人家庭。献立を主に考える成人。
- 初期プラットフォーム: iOS（Expo / React Native）
- 事業目標: 継続利用と有料転換を検証し、将来的に月5万円の営業利益相当（税・事業主労働対価控除前）を目指す。

## 1. プロダクトの約束
「今週何を作るか」を10分以内に決め、必要な買い物がすぐわかる。AIとの対話で一部だけ変更でき、週をまたいで好みを引き継ぐ。

## 2. ターゲット / ジョブ
- 主対象: 忙しい家庭で毎週の夕食を考える大人
- Job-to-be-done: 週末に次週7日分をまとめて決め、平日は迷わず調理したい
- 課題: ワンパターン、家族の好み、食品ロス、買い忘れ、時短
- KPI仮説: 週1回以上献立画面を利用し、買い物リストを開く世帯の割合

## 3. MVP範囲
必須:
1. 初回プロフィール: 大人1〜5、子ども0〜5（人数は試作時の暫定UI）、苦手食材（任意）、除外食材（任意）、平日調理時間10/20/30/45分、予算は任意の参考値
2. 7日分の夕食献立: 月〜日、料理名、所要時間、食数、任意の副菜
3. 1日単位の置換: 候補から選択、または自然言語でAIに依頼。他の日は保持
4. レシピ詳細: 材料・単位・分量・調理手順。分量は人数連動
5. 買い物リスト: 食材の正規化、同単位集計、カテゴリ表示、チェック、手動追加/削除/修正、在庫品除外
6. 保存/再訪: 端末内保存、過去週閲覧。クラウド同期は認証後の段階導入
7. AI連携: レシピIDの選択/置換を構造化出力。安全なサーバー経由。失敗時はルールベース候補
8. 基本イベント計測: onboarding_completed / plan_created / plan_replaced / shopping_opened / week_returned / paywall_viewed（個人名・会話本文は送らない）

明確に対象外（MVP）:
- 生鮮食品の現在価格予測、最安店舗検索
- 食品の撮影認識、栄養・カロリーの医療的保証
- 家族メンバーの共同編集/招待
- 配送/EC決済/外部ストア注文
- 朝食・昼食の完全対応

## 4. 主要ユーザーストーリーと受け入れ条件
### US-01 家族条件
利用者として人数・苦手な食材・調理時間を指定したい。
- 入力検証、編集、ローカル保存、再起動後復元
- 未入力の任意項目があっても先へ進める
- アレルギー等の除外条件を『安全保証』とは表示しない

### US-02 7日分の献立
利用者として1週間の献立を1回で作成したい。
- 指定週の月曜日起点で7行、重複日なし
- 料理は存在するrecipe_idに限定
- 一部生成失敗でも既存献立を壊さない
- 10分以内に週の献立を決められる体験を目指す（検証指標）

### US-03 1日だけ変更
利用者として水曜の料理だけ変えたい。
- 1日分のみ更新され残り6日が不変
- 変更後に食材の買い物リストが更新
- 保存失敗時は元の週を維持

### US-04 買い物リスト
利用者として買うものを一覧で確認したい。
- 同一食材、互換単位だけ集約（gとkgなど）。個とgを無理に足さない
- 量と単位を明示、在庫チェックで購入対象から除外
- 店舗や画面遷移後もチェック状態保持
- 自動生成した量は目安としてユーザーが調整可能

### US-05 過去の献立
利用者として先週の献立を見返したい。
- 前週/翌週へ移動、対象週のデータを復元
- 保存のない週に空状態と再生成操作

### US-06 安全なAI利用
- クライアント側にAI APIシークレットを含めない
- 認証、利用上限、リクエストサイズ制限、入力/出力検証
- AI生成結果は食品データの真実とみなさずレシピ台帳のIDで照合
- AIによる提案に誤りがありうる旨を表示。食品アレルギーは商品表示等で再確認してもらう

## 5. 料金案（正式価格ではない）
- Free: 週1回AI生成、週3回AI置換、基本買い物リスト、直近2週の履歴、手動編集は無制限
- Premium（仮480円/月）: 週5回AI生成、月60回AI置換/相談、全履歴、家族の好みを用いる詳細提案
- 『無制限AI』は原価リスクがあるため避ける。家族共有などは後日追加
- 有料化は実利用と支払意思検証後。決済内容、更新、解約、復元、料金、使用上限を明示する

## 6. 画面・導線（詳細は 02_画面と技術設計.md）
初回オンボーディング → 今週の献立 → (日別詳細・変更 / AI相談) → 買い物リスト → 過去の献立。
常設タブ: 今週 / 買い物 / 設定。AI相談は今週画面内の導線。

## 7. 品質と非機能要件
- 日本語/iPhoneを優先。片手操作、タップ領域、読みやすい文字
- 起動と画面切替時の空状態・読み込み・失敗・再試行を必ず用意
- AI障害時の代替ルートを用意し、決まった献立は失わない
- データ削除・アカウント削除、プライバシーポリシー、利用規約を公開前に整備
- Supabase RLS: 利用者は自己世帯分のみアクセス。別ユーザーの閲覧/更新/削除を禁止
- 機密鍵はサーバーだけ。CIでsecretスキャン、依存監査、環境変数の公開範囲点検
- レシピ原稿と画像は自作/適切な権利を得たもののみ使用

## 8. 成功/撤退・方向転換基準（仮説、実績ではない）
- テスター10世帯以上を確保、2週間利用
- 初回で献立が完成する割合 >= 70%
- 2週目にも新しい献立を作る割合 >= 35%
- 献立作成者の買い物リスト利用率 >= 50%
- 直近4週間のAI API+サーバー変動費を会員1人当たり予算内に抑える
- 上記の不足が判明したら有料課金や追加機能よりUX改善を優先
- 支払意思は仮の有料画面やインタビューで検証。未実装の機能で課金しない

## 9. 課金・公開留意点（2026-11-17時点）
- iOSアプリ内デジタル機能の月額課金はApple In-App Purchaseを採用する方針
- 日本のApp Storeについて、Small Business Program参加者はアプリ内購入でApple手数料10%+決済処理5%という公表条件。適用条件と税額を確認
- RevenueCatのExpo Preview API Modeは購入シミュレーション用。本番Sandbox検証はdevelopment build必須
- アカウント作成を提供する場合はアプリ内から削除を開始できる機能が必要
- Apple Developer Program: 年99米ドル（地域で表示価格変動）
